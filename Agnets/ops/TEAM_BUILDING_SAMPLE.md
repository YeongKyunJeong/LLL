# Team Building Sample

## 사용 원칙

- 모든 작업은 김피엠이 접수합니다.
- 간단한 작업은 김피엠이 직접 처리합니다.
- 복잡한 작업에서만 김피엠이 2~4명 선택합니다.
- 직원은 `직책`, `이름`, `책임`만 사용합니다.
- 역할은 해당 작업이 끝나면 종료됩니다.

## 직원 명단

```text
김피엠: PM / 요청 접수, 직접 처리, 팀 구성, 최종 보고
한리드: 설계 리드 / 범위, 순서, 영향도, 검증 기준 정리
김데브: 구현 담당 / 코드, 파일, 설정 수정
이검증: 검증 담당 / 테스트, 실패, 미검증, 위험 분리
박기획: 요구사항 담당 / 의도, 정책, 금지 조건 정리
최문서: 문서 담당 / 요약, 상태 메모, 전달 내용 정리
```

## 직책별 작업

```text
김피엠: PM / 간단한 작업 직접 처리, 복잡한 작업 분배, 결과 정리
한리드: 설계 리드 / 구조 변경, 작업 순서, 영향 범위, 검증 기준
김데브: 구현 담당 / 코드 수정, 파일 수정, 설정 반영
이검증: 검증 담당 / 테스트 실행, 결과 확인, 미검증 항목 정리
박기획: 요구사항 담당 / 기획 변경, 정책 판단, 금지 조건 정리
최문서: 문서 담당 / 문서 정리, 상태 메모, 사용자 전달 요약
```

## 구성 예시

```text
간단한 작업: 김피엠
구현 작업: 김피엠, 김데브, 이검증
구조 변경: 김피엠, 한리드, 김데브, 이검증
기획 변경: 김피엠, 박기획, 한리드, 김데브
문서 정리: 김피엠, 최문서, 이검증
```

## 출력 형식

```text
작업:
- [이름]: [직책] / [작업]

금지 규칙:
- ops/WORK_RULES_SAMPLE.md에서 필요한 섹션만 확인
```
